# Frontend redesign baseline

Контракты данных и навигации зафиксированы в [API_CONTRACTS.md](./API_CONTRACTS.md).
Правила визуального слоя и базовые компоненты описаны в [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md).

Зафиксировано перед поэтапным редизайном frontend. Этот документ описывает
минимальный набор маршрутов и сценариев, которые должны оставаться рабочими на
каждом этапе.

Дата baseline: 2026-09-19.

## Правила совместимости

- Не удалять существующие маршруты и API без совместимого переходного периода.
- Не изменять идентификаторы проектов, страниц, задач, событий и участников.
- Не удалять пользовательские данные, типы блоков и загруженные файлы.
- Изменения хранилища выполнять только добавочными миграциями с резервной копией.
- Сохранять глубокие ссылки на задачи, страницы и возврат в панель администратора.
- Новый интерфейс должен использовать существующие store, API и проверки доступа.
- Не копировать бизнес-логику в параллельные версии страниц.

## Маршруты

| Экран | Маршрут | Доступ |
| --- | --- | --- |
| Мои проекты | `/` | Авторизованный пользователь |
| Сегодня | `/today` | Авторизованный пользователь |
| Мои задачи | `/my-tasks` | Авторизованный пользователь |
| Мой календарь | `/my-calendar` | Авторизованный пользователь |
| Личные настройки | `/settings` | Авторизованный пользователь |
| Системный администратор | `/system-admin` | Владелец продукта |
| Канбан | `/board/:projectId` | Участник проекта |
| Workspace | `/project/:projectId/workspace` | Участник проекта |
| Страница | `/project/:projectId/workspace/page/:pageId` | Участник проекта |
| Входящие | `/project/:projectId/inbox` | Участник проекта |
| Уведомления | `/project/:projectId/notifications` | Участник проекта |
| Напоминания | `/project/:projectId/reminders` | Участник проекта |
| Календарь проекта | `/project/:projectId/calendar` | Участник проекта |
| Участники | `/project/:projectId/members` | Участник проекта |
| Администратор проекта | `/project/:projectId/settings` | По роли проекта |
| Архив | `/project/:projectId/archive` | Участник проекта |

Неизвестный маршрут перенаправляется на `/`. Проектные маршруты защищены
`ProjectAccessGate`.

## Критические сценарии

1. Вход через Telegram Mini App и вход по Telegram-нику с шестизначным кодом.
2. Создание проекта, открытие проекта и ввод кода приглашения.
3. Создание папки, страницы, канбан-доски и загрузка файла через Workspace.
4. Открытие существующей страницы и сохранение всех поддерживаемых блоков.
5. Создание, редактирование, перенос и архивирование задачи.
6. Определение крайней правой канбан-колонки как завершенной.
7. Переход к задаче из Today, My Tasks, уведомлений и панели администратора.
8. Возврат к исходному экрану после открытия задачи по глубокой ссылке.
9. Создание личного и проектного события календаря.
10. Отображение категорий, дедлайнов, внешних календарей и уведомлений.
11. Работа Inbox, напоминаний, упоминаний и Telegram-уведомлений.
12. Загрузка, открытие и скачивание проектных файлов.
13. Управление участниками, ролями и проектными правами.
14. Работа вкладок администратора проекта и AI Connector.
15. Запрет доступа к чужому проекту на backend, а не только в интерфейсе.

## Визуальная фиксация

Контрольные изображения первого viewport находятся в:

- `screenshots/mobile` для размера 390 x 844;
- `screenshots/desktop` для размера 1440 x 1000.

Зафиксированы 15 основных экранов. Конкретная страница Workspace дополнительно
проверяется в сценарном тестировании, так как ее содержимое зависит от выбранного
типа страницы.

## Проверка после каждого этапа

1. Frontend production build.
2. Backend API smoke test.
3. Сборка Telegram-бота.
4. Проверка авторизации и прав доступа.
5. Проверка критических сценариев затронутого модуля.
6. Сравнение mobile и desktop с baseline.
7. Проверка консоли браузера и сетевых ошибок.
8. Отдельный коммит, позволяющий откатить этап целиком.

## Контрольные показатели сборки

Проверки baseline от 2026-09-19:

- frontend: `npm run build` успешно;
- Telegram-бот: `npm run build` успешно;
- backend API: `npm run smoke` успешно;
- файловые адаптеры: `npm run test:file-storage` успешно;
- Docker Compose config локально не проверен, потому что Docker CLI не установлен
  на рабочем компьютере; проверка остается обязательной на staging/сервере.

Крупнейшие frontend-чанки baseline до gzip:

| Чанк | Размер |
| --- | ---: |
| `vendor-react` | 161.46 kB |
| `SettingsPage` | 154.28 kB |
| `PageEditor` | 127.92 kB |
| `CalendarPage` | 54.24 kB |
| `vendor-dnd` | 48.94 kB |
| CSS | 44.48 kB |

Эти значения не являются лимитами сами по себе, но заметный рост должен быть
объяснен в коммите и проверен на мобильном Telegram WebView.

## Хранение данных

Production-данные не входят в Git. Docker Compose хранит базу и локальные файлы
в именованном томе `nototime-app-data`, подключенном к API как `/data`.
Обновление frontend не должно изменять этот том.
