# Адаптивная оболочка приложения

На этапе 3 добавлена единая оболочка личных разделов. Она отвечает только за
композицию экрана и навигацию; данные страниц, API-запросы и права доступа
остаются внутри существующих модулей.

## Маршруты внутри оболочки

| Раздел | Маршрут | Пункт навигации |
| --- | --- | --- |
| Проекты | `/` | Проекты |
| Сегодня | `/today` | Сегодня |
| Личный календарь | `/my-calendar` | Календарь |
| Мои задачи | `/my-tasks` | Задачи |
| Личные настройки | `/settings` | Профиль |

`NavLink` определяет активный раздел по URL. Корневой маршрут использует точное
совпадение, поэтому пункт «Проекты» не подсвечивается на остальных страницах.

## Адаптивное поведение

- До breakpoint `md` навигация находится в отдельной нижней строке grid.
- Нижняя панель не использует `position: fixed` и не перекрывает содержимое.
- Учитывается `env(safe-area-inset-bottom)` мобильных устройств.
- Начиная с `md` нижняя панель заменяется боковой навигацией шириной 224 px.
- Рабочая область всегда получает `min-width: 0` и `min-height: 0`, поэтому
  внутренние скроллеры таблиц, календаря и списков сохраняют своё поведение.

## Изоляция проектных экранов

Проектные Workspace, канбан, Inbox, напоминания, календарь проекта, участники и
панель администратора не вложены в личную оболочку. У них уже есть собственный
контекст навигации и проектные права. Их перенос должен выполняться отдельным
этапом после проектирования project shell, чтобы не появилось две панели сразу.

## Иконки

Навигация использует `lucide-react`. Импортируются только нужные React-компоненты,
поэтому Vite исключает остальные иконки при production-сборке. Текстовые подписи
сохранены и не заменены иконками, чтобы разделы были однозначны и доступны.

## Правила расширения

1. Новый личный маршрут добавляется одновременно в `App.tsx` и карту навигации.
2. Пункт должен иметь короткую подпись, помещающуюся на ширине 320 px.
3. Не размещать внутри страницы вторую основную навигацию с теми же маршрутами.
4. Модальные окна должны иметь `z-index` выше оболочки.
5. После изменения проверять все пять маршрутов на mobile и desktop.
