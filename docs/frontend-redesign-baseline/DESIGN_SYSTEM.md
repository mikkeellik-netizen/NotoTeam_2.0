# Дизайн-система NotoTime

Основа дизайн-системы добавлена на этапе 2 редизайна. Она меняет только слой
представления и не затрагивает API, маршруты, stores, права доступа или формат
пользовательских данных.

## Принципы

- Один семантический токен описывает назначение цвета, размера или отступа.
- Компоненты приложения используют `--nt-*`, а не собственные значения цвета.
- Переменные Telegram остаются совместимым источником темы для Mini App.
- Светлая и тёмная темы меняют значения токенов, а не разметку страниц.
- Радиус рабочих элементов ограничен 8 px, чтобы интерфейс оставался компактным.
- Новые компоненты должны поддерживать клавиатуру, видимый focus и подписи ARIA.
- Миграция выполняется по одному экрану; параллельные версии бизнес-логики не создаются.

## Токены

Файл: `frontend/src/design-system/tokens.css`.

| Группа | Назначение | Примеры |
| --- | --- | --- |
| Цвета | фон, поверхности, текст, границы, состояния | `--nt-color-canvas`, `--nt-color-danger` |
| Типографика | семейства и фиксированная шкала текста | `--nt-font-sans`, `--nt-text-lg` |
| Отступы | единая шкала 4–32 px | `--nt-space-2`, `--nt-space-6` |
| Размеры | высоты контролов и ширины контента | `--nt-control-md`, `--nt-content-lg` |
| Форма | радиусы поверхностей и контролов | `--nt-radius-control` |
| Эффекты | тени, focus ring и скорость анимации | `--nt-shadow-md`, `--nt-motion-fast` |

Прямые `hex`, `rgb`, произвольные радиусы и тени допустимы только при добавлении
нового документированного токена. Исключение: цвета пользовательского контента,
например цвет календаря или категории события.

## Базовые компоненты

Экспортируются из `frontend/src/components/ui/index.ts`.

| Компонент | Для чего использовать |
| --- | --- |
| `Button` | основные, вторичные, текстовые и опасные действия |
| `IconButton` | компактная кнопка с обязательным `aria-label` |
| `TextField` | однострочный ввод, подпись, подсказка и ошибка |
| `TextArea` | многострочный ввод |
| `Select` | выбор одного значения |
| `Surface` | рабочая поверхность или отдельный самостоятельный блок |
| `Tabs` | переключение между представлениями одного раздела |
| `Modal` | диалог с Escape, focus trap, overlay и мобильным sheet-режимом |

Компоненты принимают обычные DOM-свойства. Специфичная бизнес-логика остаётся в
странице или feature-компоненте и не переносится в дизайн-систему.

## Порядок миграции экранов

1. Заменить цвета и размеры на семантические токены без изменения структуры.
2. Заменить повторяющиеся кнопки, поля и модальные окна на UI-компоненты.
3. Проверить светлую и тёмную темы, desktop и mobile.
4. Проверить клавиатурную навигацию и длинный русский текст.
5. Выполнить production build и контрактные тесты.
6. Только после этого менять композицию и визуальную иерархию экрана.

## Текущее покрытие

На этапе 2 компоненты подключены к экрану входа и системным состояниям приложения.
Остальные страницы продолжают работать на прежней разметке и будут переноситься
поэтапно. Это позволяет оценивать каждое изменение отдельно и сохранять простой
откат без риска для данных проекта.
